% ==========================================
% ABSTRACT
% ==========================================
\begin{abstract}
Sensing infrastructure capable of detecting spatial presence increasingly operates independently from institutional scheduling databases, preventing automated evaluation of whether observed presence aligns with scheduled obligations. This work presents a relational evaluation framework that continuously reconciles spatial detection events with institutional schedules through formally defined predicate logic.

The framework introduces the Continuous Predicate Evaluation Model (CPEM), which represents institutional rules as relational predicates evaluated over streaming event tuples. To reduce spurious violations caused by short-lived sensor noise and transit behavior, the evaluation logic incorporates a Persistent Constraint Violation Filter (PCVF) that temporally stabilizes logical state transitions through sustained violation integration. Spatial exclusivity constraints further prevent inconsistent multi-zone detections from propagating into the evaluation layer.

To sustain synchronized burst traffic during class transitions, the relational pipeline integrates transaction-level connection pooling, list-based table partitioning, and composite temporal indexing within PostgreSQL. Experimental load testing demonstrates that the evaluation layer maintains sub-15 ms p99 latency at approximately 5,000 QPS under burst conditions, confirming that continuous schedule reconciliation can operate within bounded evaluation latency when relational access paths are systematically optimized.
\end{abstract}

\begin{IEEEkeywords}
Continuous Predicate Evaluation, Spatiotemporal Compliance, Relational Stream Processing, Temporal Debounce Logic, Burst-Resilient Query Optimization.
\end{IEEEkeywords}

% I. INTRODUCTION
% ==========================================
\section{Introduction}

The dominant thesis of this paper is that \textbf{continuously evaluated relational predicates enable bounded-latency reconciliation between spatial event streams and institutional schedules under burst-concurrent conditions}. This paper functions as a relational stream-evaluation study, focusing strictly on spatiotemporal logic and query optimization rather than generalized institutional surveillance.

\subsection{The Temporal Blindness of Snapshot Attendance Systems}
Traditional attendance procedures suffer from temporal blindness. Single-point verification—such as an RFID swipe or biometric check—implicitly assumes future compliance based on instantaneous confirmation. However, spatial state changes occur continuously after verification. Static attendance cannot capture mid-session deviations, transit delays, or early departures. Schedule legitimacy requires temporal continuity rather than discrete confirmation; the core challenge is continuous relational reconciliation over event streams, not merely presence detection accuracy.

\subsection{Subsystem Scope and Canonical Separation}
Within the ScholarMaster architecture, this subsystem reconciles spatial events with schedules, evaluates compliance predicates continuously, stabilizes transient violations, and sustains bounded-latency query behavior. This subsystem does NOT detect localized acoustic anomalies (Paper 6), coordinate activation and orchestration policy (Paper 9), manage cryptographic provenance (Paper 8), perform sensing inference, or conduct behavioral analytics.

\subsection{Continuous Predicate Evaluation}
Closing the semantic gap between sensing layers and schedule databases requires rethinking compliance evaluation. The evaluation function proposed here operates on presence as a continuous stream rather than a snapshot. The logical pipeline evaluates event tuples over time \cite{b14}, representing compliance as a temporally evolving relational state. This aligns with established real-time stream processing principles \cite{b13}.

\subsection{Contributions}
Implementing continuous compliance evaluation required several adaptations within the relational pipeline. The primary focus is the evaluation logic necessary to make continuous reconciliation viable under institutional-scale burst traffic.

Specifically, this paper:
\begin{itemize}
    \item Formalizes spatiotemporal compliance rules as continuously evaluated relational predicates (CPEM), enabling schedule comparison at event granularity.
    \item Introduces a temporally stabilized violation mechanism (PCVF) to suppress short-lived mismatches caused by transit or sensor instability.
    \item Establishes spatial exclusivity invariants to prevent logically inconsistent upstream detections from contaminating the evaluation layer.
    \item Optimizes relational read paths using connection pooling, table partitioning, and composite indexing to sustain burst concurrency.
\end{itemize}

Sensing, identity resolution, and governance escalation are treated as external subsystem dependencies; this work isolates the relational predicate evaluation layer.

% II. RELATED WORK

\section{Related Work}

\subsection{Limitations of Passive Evaluation}
Existing institutional monitoring systems often emphasize detection accuracy but provide limited mechanisms for real-time schedule reconciliation. Much infrastructure is designed for post-event analysis rather than live evaluation. Without automated filtering, operationally relevant anomalies remain embedded in event streams that exceed human monitoring capacity \cite{b7}. Manually correlating observed identities with dynamic timetables is impractical at institutional scale.

The approach developed here emphasizes exception-based evaluation. Human attention is engaged only when a formally defined deviation persists beyond the debounce threshold \cite{b17}, reducing monitoring burden while preserving operational responsiveness.

\subsection{Discrete Verification versus Continuous Reconciliation}
RFID badges and biometric entry systems verify presence at specific checkpoints \cite{b2, b3}. These systems log facility entry but do not evaluate subsequent spatial behavior. Once marked present, a student's compliance status typically remains static until manually updated.

Continuous zone-based evaluation extends this model substantially. By integrating moving-object database principles \cite{b15, b16}, the evaluation logic dynamically reconciles spatial presence with scheduled expectations throughout the session rather than at a single timestamp. The distinction is architectural: discrete verification produces a snapshot, while continuous reconciliation produces a stream of evaluated predicates.

\subsection{Stream Processing and Spatiotemporal Coordination}
Recent work in edge-intelligent systems emphasizes dense IoT integration for operational visibility \cite{b1}. Multimodal fusion approaches have enhanced situational awareness across domains \cite{b6}. The present work applies similar coordination principles specifically to schedule adherence, integrating detection events \cite{b23} with centralized relational records.

The emphasis here is on relational reconciliation rather than perceptual optimization---a distinction that positions this work closer to stream-processing systems research \cite{b22} than to computer vision or behavioral analytics.

% III. OPERATIONAL MODEL
% ==========================================
\section{Operational Model}

\subsection{Context-Blindness in Edge Sensors}
Edge detection systems are typically optimized for perception tasks rather than policy interpretation \cite{b5}. They can identify an opaque identity token and associate it with a specific zone at a given timestamp, but they cannot determine whether that presence is legitimate relative to institutional rules.

Consider two identical physical observations at 14:30:
\begin{itemize}
    \item \textbf{Scenario A:} Student $X$ is detected at the Exit Gate. The schedule indicates campus dismissal. $\rightarrow$ \textit{Evaluation: Compliant.}
    \item \textbf{Scenario B:} Student $X$ is detected at the Exit Gate. The schedule indicates mandatory laboratory. $\rightarrow$ \textit{Evaluation: Non-compliant.}
\end{itemize}

From the sensor’s perspective, both observations are equivalent. The semantic difference emerges only when the spatial event is reconciled with the schedule. The predicate evaluation yields a formal compliance state.

\subsection{Continuous Predicate Evaluation Model (CPEM)}
Compliance is modeled not as a one-time attendance decision, but as a temporally evolving relational state. The CPEM formalizes this by translating schedule states into continuous predicates evaluated against event streams. Let the sensor event stream be defined as:
\begin{equation}
E = \{(s_i, z, t)\}
\end{equation}
where:
\begin{itemize}
    \item $s_i$ denotes an opaque identity token,
    \item $z$ denotes the detected physical zone,
    \item $t$ denotes the timestamp.
\end{itemize}
Compliance is evaluated by comparing observed location $\text{Loc}(s_i, t)$ with the scheduled expectation $S(s_i, t)$. We define the deviation predicate:
\begin{equation}
T(s_i, t) \iff \text{Loc}(s_i, t) \neq S(s_i, t) \land S(s_i, t) \notin \{\emptyset, \text{Break}\}
\end{equation}
If the schedule is empty (e.g., free period or transit window), the presence is considered compliant unless it falls within a restricted zone. This formulation shifts adherence from a discrete check to a continuously evaluated relational predicate.

\subsection{Spatial Exclusivity Invariant}
Robust relational operation requires defensive handling of upstream inconsistencies; spatial exclusivity is elevated as a fundamental logical consistency safeguard, not merely an anomaly heuristic. Contradictory spatial states contaminate downstream evaluation.

We enforce the spatial exclusivity invariant:
\begin{equation}
|\{z : \text{Loc}(s_i,t)=z\}| \le 1
\end{equation}
An identity token cannot exist simultaneously in disjoint zones. If conflicting detections arrive for the same timestamp, the evaluation layer flags a teleportation anomaly, which inherently violates relational coherence, and suspends evaluation for that token until the state stabilizes. This exclusivity enforcement preserves predicate validity and prevents contamination of the relational layer.

\section{Abstract Processing Model}

To operationalize real-time compliance evaluation, we assume a logical processing model positioned between an incoming event stream and a relational schedule store.

\subsection{End-to-End Logic}
We assume an event stream and a relational store. Event tuples containing identity and resolved zones are ingested as inputs. These inputs are buffered to maintain historical continuity for debounce filtering. Finally, they are evaluated against a relational database (e.g., PostgreSQL), which serves as the authoritative schedule source, returning expected zones for validation.

\subsection{Zone Mapping and Resolution}
Zone identifiers are statically mapped via a central configuration registry. The evaluation logic receives resolved zone labels directly, eliminating the need for geometric boundary computation. By decoupling geometric reasoning from compliance logic, the computational complexity within the relational fusion layer is reduced.

% ==========================================
% V. DATA SANITIZATION & DEBOUNCE LOGIC
% ==========================================
\section{Data Sanitization \& Debounce Logic}

\subsection{Persistent Constraint Violation Filter (PCVF)}
Sensor-driven zone transitions frequently contain transient noise that can lead to unstable compliance evaluations. Transient mismatches emerge naturally from movement and sensing instability. Evaluating each event independently could unnecessarily inflate false alerts. PCVF stabilizes logical state transitions over time rather than merely smoothing noisy data, recognizing that sustained deviations are operationally more meaningful than instantaneous mismatches.

Instead, deviation is treated as a time-accumulated state. We define the sustained violation integral:
\begin{equation}
V(s_i,t) = \int_{t_0}^{t} \mathbb{1}_{T(s_i,\tau)} d\tau
\end{equation}
To approximate a rectangular low-pass filter, we compute:
\begin{equation}
\hat{T}(t) = \frac{1}{\tau_{debounce}} \int_{t-\tau_{debounce}}^{t} T(\tau') d\tau'
\end{equation}
In implementation, the integral is discretized over event timestamps. An alert is emitted only when:
\begin{equation}
V(s_i, t) \ge \tau_{debounce}
\end{equation}
Short-lived mismatches are absorbed as transient noise. Sustained deviations eventually trigger escalation. The logic maintains an in-memory LRU cache to track violation windows efficiently without excessive database interaction.

\subsection{Hysteresis Handling}
If an identity briefly disappears from the feed (e.g., occlusion) and reappears within a predefined hysteresis window in the same zone, the violation integral continues uninterrupted. If the identity reappears in a different zone, the integral resets.

This state-machine behavior (Figure \ref{fig:fsm}) stabilizes evaluation across intermittent signal loss while preserving responsiveness to genuine zone changes.

% --- ALGORITHM 1: DATA SANITIZATION ---
\begin{algorithm}[htbp] % <--- CHANGED FROM [H] TO FIX SPACING
\caption{Temporal Debounce Filtering (PCVF)}
\begin{algorithmic}[1]
\REQUIRE Incoming Event Stream $S$, Threshold $\tau_{debounce}$
\ENSURE Validated Logic Events $E$
\FOR{each event $e$ in $S$}
    \STATE $ID \leftarrow e.identity$
    \STATE $Zone \leftarrow e.zone$
    \STATE $StateBuffer[ID].append(Zone, now())$
    \STATE
    \STATE \textbf{// Check contiguous duration in current zone}
    \IF{$\text{Duration}(StateBuffer[ID] == Zone) \ge \tau_{debounce}$}
        \STATE $E.add(ID, Zone)$ \COMMENT{Promote to stable event}
    \ELSE
        \STATE \textbf{Drop} \COMMENT{Filter as transient noise}
    \ENDIF
\ENDFOR
\RETURN $E$
\end{algorithmic}
\label{alg:sanitization}
\end{algorithm}

% ==========================================
\section{Burst-Elastic Read Optimization}

Synchronized class transitions generate short bursts of extremely high event traffic. Latency reduction emerges from controlled relational-access behavior rather than fundamentally novel database theory. Throughput improvements emerge from relational access-path reduction, where pooling stabilizes concurrency pressure and partitioning narrows lookup scope.

\subsection{Schema Partitioning Strategy}

The \texttt{student\_schedule} table is partitioned by \texttt{day\_of\_week}, immediately reducing search scope to a single partition. This reduces unnecessary cross-day scanning and constrains index traversal depth.

% --- LISTING 1: SQL SCHEMA ---
\begin{figure}[htbp] % <--- CHANGED FROM [H] TO FIX SPACING
\centering
\textbf{Listing 1: PostgreSQL Schedule Schema}
\begin{lstlisting}[language=SQL]
CREATE TABLE student_schedule (
  student_id VARCHAR(50) NOT NULL,
  day_of_week VARCHAR(3) CHECK (
    day_of_week IN ('MON','TUE','WED','THU','FRI')),
  start_time TIME NOT NULL,
  end_time TIME NOT NULL,
  expected_zone_id VARCHAR(50),
    
  PRIMARY KEY (student_id, day_of_week, start_time)
) PARTITION BY LIST (day_of_week);
\end{lstlisting}
\label{code:sql}
\end{figure}

When a stable event passes the PCVF layer, the logic issues a point-in-time query:
\begin{lstlisting}[language=SQL]
SELECT expected_zone_id FROM student_schedule 
WHERE student_id = ? AND day_of_week = ? 
AND start_time <= ? AND end_time >= ?
\end{lstlisting}

\subsection{Composite Temporal Indexing}
A composite B-Tree index \cite{b18} is applied across identity and temporal fields:
\begin{lstlisting}[language=SQL]
CREATE INDEX idx_temporal_lookup ON 
  student_schedule (student_id, day_of_week, start_time, end_time);
\end{lstlisting}
Given limited per-student schedule cardinality, this index rapidly narrows candidate intervals prior to temporal comparison \cite{b19}. The majority of latency arises from network and I/O overhead rather than index traversal.

\subsection{Connection Pooling and Capacity Stabilization}
During burst transitions, connection setup overhead can dominate query time. Without pooling:
\begin{equation}
T_{query} = T_{exec} + T_{conn}
\end{equation}
When $T_{conn}$ becomes significant, effective service capacity ($\mu$) collapses under high arrival rate ($\lambda$).

Transaction-level connection pooling removes this overhead from the critical path:
\begin{equation}
T_{query} \approx T_{exec}
\end{equation}
This data architecture adjustment significantly increases sustainable throughput and prevents connection exhaustion during thundering herd scenarios \cite{b20, b24}.

\section{Experimental Evaluation}

\subsection{Evaluation Scope and Environment}
Evaluation focuses on two operational characteristics: lookup responsiveness and stability during burst traffic conditions. All results are derived from synthetic load testing designed to validate logical correctness and database throughput. The objective was not to model real campus demographics, but to stress the relational layer under controlled conditions.

Tests were executed on:
\begin{itemize}
    \item 16-core AMD EPYC server
    \item 64 GB RAM
    \item PostgreSQL 15
    \item \texttt{shared\_buffers} = 8GB
\end{itemize}
Each experiment was repeated five times with randomized identity distributions to smooth out skew from repeated key reuse patterns.

\subsection{Latency Decomposition}
Real-time responsiveness represents an important operational requirement. Rather than reporting a single aggregate metric, we decomposed latency into its constituent components.

The majority of latency originates from the relational lookup stage. Predicate evaluation itself contributes only a small portion of total latency relative to network and I/O costs. This reinforces an important design observation: compliance complexity does not meaningfully affect response time once the relational access path is optimized. Even under moderate concurrency, the evaluation layer consistently remained within single-digit millisecond latency.

\subsection{Throughput and Concurrency Stress Testing}
To evaluate burst resilience, the database was flooded with pre-generated identity tokens representing synthetic institutional burst conditions. Load was increased incrementally to 6,000 QPS.

Without connection pooling, the system began to degrade past 3,000 QPS. Tail latency rose sharply as connection overhead accumulated, confirming the expected $T_{conn}$ bottleneck.

With transaction-level pooling enabled, the latency curve flattened substantially. Within the evaluated burst conditions and the observed database configuration, the evaluation layer sustains approximately 5,000 QPS while maintaining sub-15 ms p99 latency ($\pm 1.2$ ms standard deviation). QPS scaling ultimately depends on deployment-specific hardware and network topology; these results reflect evaluated workload assumptions rather than universally guaranteed scalability.

\textbf{Scenario 1: Rapid Multi-Zone Transitions}\\
An agent traversed multiple restricted zones within a short time interval.
\textit{Result:} The PCVF state machine absorbed these transitions as transient noise. Because the violation integral never exceeded $\tau_{debounce}$, no alert was emitted. This confirmed that transit behavior does not trigger false escalation.

\textbf{Scenario 2: Intermittent Signal Loss}\\
An agent’s signal was intentionally dropped for two seconds before reappearing in the same zone.
\textit{Result:} The hysteresis buffer preserved the accumulated violation state. When the signal resumed, the debounce timer continued rather than resetting. Sustained violations were therefore still detected.

\textbf{Scenario 3: Backend Service Interruption}\\
The database connection was manually severed during active processing.
\textit{Result:} The logic trapped the exception and allowed the upstream event queue to buffer unread events. Upon restoration, the queue drained without data loss. No corrupted states were observed in the relational layer.

These controlled tests suggest that the evaluation logic remains stable under common operational disruptions.

\section{Discussion}

\subsection{Logic Decoupling and Extensibility}
Isolating compliance evaluation within relational predicate logic yields a significant extensibility benefit: the evaluation layer is agnostic to how identity is resolved. Optical recognition, RFID badges, WiFi triangulation, or future sensing modalities can all feed the same tuple:
\begin{equation}
(ID, Zone, Timestamp)
\end{equation}
As long as this abstraction is respected, the relational predicate layer functions identically regardless of the upstream sensing technology. This separation also simplifies logic evolution---improvements to detection quality do not require modification of the evaluation query, and new compliance rules can be expressed as additional predicates without altering the processing pipeline.

\subsection{Predicate Auditability}
A practical advantage of continuous relational evaluation is that every compliance decision can be reconstructed from its constituent inputs. For any flagged deviation, the system can produce the original event tuple, the schedule record it was evaluated against, the PCVF integration state at the time of escalation, and the spatial exclusivity check result. This traceability is a structural property of predicate-based evaluation rather than a post-hoc logging feature.

In institutional environments where compliance decisions may face administrative review, the ability to reconstruct the evaluation path is operationally significant. Opaque behavioral inference models, by contrast, cannot typically provide equivalent decision traceability.

\subsection{Limitations}
The present system evaluates schedule compliance strictly through relational comparison. It does not attempt behavioral inference beyond zone adherence. This constraint preserves logical clarity and evaluation latency but explicitly limits the system's analytical scope.

All evaluation results are derived from synthetic workload testing rather than live institutional traffic. While the load profiles approximate burst patterns during class transitions, real deployment introduces variability---network jitter, transaction spikes during synchronized transitions, schedule-update propagation lag, sensor timestamp drift, and temporary backend interruptions---that synthetic testing cannot fully replicate.

Furthermore, the evaluation layer maintains absolute dependence on upstream sensing quality. If the sensing subsystem produces systematically delayed or inaccurate zone labels, the PCVF may absorb genuine deviations as transient noise. The debounce threshold ($\tau_{debounce}$) represents a highly sensitive calibration tradeoff between transient suppression and detection responsiveness.

\section{Conclusion}
This relational stream-evaluation study presented a pipeline for continuously reconciling spatial detection events with institutional schedule constraints through formally defined predicate logic. By representing institutional rules as continuously evaluated spatiotemporal predicates (CPEM) and applying a temporally stabilized violation filter (PCVF), the evaluation logic distinguishes sustained deviations from transient sensor noise while maintaining relational state coherence.

From an infrastructure perspective, latency reduction emerges from controlled relational-access behavior. Partitioned schema design, composite temporal indexing, and transaction-level connection pooling enable the relational lookup layer to sustain burst traffic approaching 5,000 QPS while maintaining sub-15 ms p99 latency---confirming that the relational coordination overhead remains bounded under evaluated burst conditions.

The design intentionally favors operational predictability over analytical breadth. Within the broader ScholarMaster ecosystem, this subsystem functions exclusively to evaluate continuous compliance predicates and perform bounded-latency relational reconciliation. It does not orchestrate activation governance (Paper 9) or perform acoustic anomaly sensing (Paper 6). It consumes abstract spatial event tuples and emits evaluated predicate states, prioritizing temporal stabilization and burst-resilient lookup behavior over universal institutional monitoring.
