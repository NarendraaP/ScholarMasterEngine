% ==========================================
% ABSTRACT
% ==========================================
\begin{abstract}
Edge deployments that combine multiple AI perception modules often encounter orchestration difficulties that are not directly related to model accuracy. Coordinating heterogeneous inference pipelines under shared latency, compute, and policy constraints introduces a system-level control problem. Tight coupling among these components can introduce cascading failure risks across the sensing pipeline, whereas cloud-mediated orchestration often conflicts with the real-time responsiveness expected in instructional settings.

To address this orchestration problem, this work introduces a hierarchical control-plane abstraction for policy-aware coordination of multi-module AI workloads at the edge. The design assumes a layered execution environment—Perception, Reasoning, and Governance—while restricting cross-layer communication to typed, bounded context vectors. To regulate computational cost, we introduce a Compute Justification Model that formalizes Inference Rate Governance (IRG). This mechanism enables dynamic activation or suppression of sensing modules according to lecture phase and predefined operational heuristics.

System resilience is evaluated via fault injection that subjects the orchestrator to deterministic failure scenarios including module timeouts, memory pressure, and routing perturbations. To evaluate orchestration behavior independently of downstream model accuracy, we define four policy-aware metrics: Inference Suppression Ratio (ISR), Ethical Compute Utilization (ECU), Context-Aware Duty Cycle (CADC), and Layer Isolation Factor (LIF). Experimental observations indicate that hierarchical orchestration can confine localized failures. It also aligns compute activation with predefined operational policies.
\end{abstract}

\begin{IEEEkeywords}
Hierarchical Orchestration, Policy-Aware Control Plane, Inference Rate Governance, Deterministic Degradation, Fault Containment, Edge-Native Activation.
\end{IEEEkeywords}

% ==========================================
% I. INTRODUCTION
% ==========================================
\section{Introduction}

The dominant thesis of this paper is that \textbf{hierarchical policy-aware orchestration enables deterministic and fault-contained coordination of heterogeneous edge AI modules under shared operational constraints}. Edge-based intelligent environments increasingly rely on multiple specialized AI modules operating concurrently, such as biometric recognition, pose estimation, and speech interpretation. Although each component can be optimized independently, coordinating them within a shared runtime introduces a distinct orchestration control problem \cite{b14, b21}.

\subsection{Architectural Fragility in Flat Multi-Model Pipelines}
When modules are tightly coupled in flat execution pipelines, localized crashes in one heavy perception model can easily propagate, causing cascading failure across the entire sensing system. Shared compute contention destabilizes otherwise independent modules, while cloud-mediated orchestration introduces unpredictable network latency that cannot support real-time interaction modeling \cite{b4, b15}. Furthermore, naive always-on sensing wastes operational resources by executing compute-intensive models when they are not contextually required. Orchestration instability emerges fundamentally from coordination topology, not merely from underlying model inefficiency.

\subsection{Contributions and Subsystem Scope}
This work investigates whether a logical control-plane abstraction can address these coordination limits. We assume a layered execution environment—Perception, Reasoning, and Governance—that enforces structured isolation. Specifically, our contributions are:
\begin{itemize}
    \item A hierarchical control-plane abstraction relying on typed context vectors for orchestration isolation \cite{b17}.
    \item A Compute Justification Model formalizing Inference Rate Governance (IRG) for policy-aligned module activation.
    \item Explicit failure containment strategies ensuring graceful degradation when individual modules fail \cite{b18}.
    \item Validation via fault injection to confirm orchestration resilience under deterministic failure scenarios \cite{b28}.
\end{itemize}

Within the ScholarMaster architecture, this subsystem coordinates module activation, governs orchestration logic, and enforces deterministic degradation only. It does not evaluate survivability envelopes (Paper 10), optimize flash endurance (Paper 12), optimize federated adaptation (Paper 13), derive runtime verification theorems (Paper 18), or define irreversible governance doctrine (Paper 17).

% II. RELATED WORK
% ==========================================
\section{Related Work}

Prior work on AI orchestration has largely focused on cloud-based coordination frameworks. Cloud platforms such as AWS IoT Hub provide robust centralized orchestration capabilities for distributed sensing systems \cite{b6}. However, the inherent latency associated with cloud round-trips frequently violates the real-time requirements necessary for classroom interaction analysis. In our design, event stream processing remains local to the edge device to maintain low-latency control loops. While recent cloud reference architectures emphasize horizontal scalability, they generally struggle with the strict latency constraints required by edge-native pedagogical analytics.

In the commercial space, affect recognition platforms typically deploy monolithic models to perform end-to-end facial emotion recognition \cite{b7}. While these systems are edge-resident, they often exhibit brittle failure modes: if the primary facial model crashes due to a corrupted input frame or memory exhaustion, the entire sensing pipeline halts. By contrast, the hierarchical design allows the orchestrator to route logic to fallback modes when necessary—such as pose-only sensing—when heavy perception models fail \cite{b24}. Furthermore, while edge frameworks like TensorFlow Lite effectively optimize individual model inference \cite{b10, b31}, they typically lack built-in mechanisms for cross-module coordination, operational policy enforcement, or failure-aware scheduling.

Federated learning frameworks, including TensorFlow Federated and PySyft, address privacy-preserving model training across distributed nodes \cite{b8}. These tools focus primarily on weight aggregation during the training phase, not on real-time inference orchestration, failure tolerance, or operational governance. Our work addresses the orthogonal challenge of coordinating pre-trained, heterogeneous models directly at inference time \cite{b23}.

Recent evaluations have shown the viability of deploying microservices at the edge for continuous video analytics \cite{b21}. Standard orchestrators, however, lack native primitives for privacy-aware module suppression. Establishing structured sensing boundaries in smart educational environments is widely recognized as a necessity. The proposed framework implements this governance directly within the orchestration plane using a Compute Justification Model, aligning the system's behavior with privacy-preserving operational norms \cite{b27}.

% ==========================================
% III. PROBLEM STATEMENT
% ==========================================
\section{Problem Statement}

Coordinating heterogeneous AI modules inside a single edge deployment introduces several competing architectural requirements:
\begin{enumerate}
    \item \textbf{Boundary Confinement:} High-fidelity perception data (like raw video frames) must remain confined to lower abstraction layers to limit unnecessary exposure to upper-layer business logic \cite{b27}.
    \item \textbf{Real-Time Responsiveness:} Cross-module coordination has to happen within tight latency envelopes to preserve systemic interactivity \cite{b21}.
    \item \textbf{Failure Tolerance:} Individual module faults should gracefully degrade overall functionality rather than halting the entire sensing system \cite{b24}.
\end{enumerate}

Architectures that strongly emphasize one of these dimensions may inadvertently compromise the others. The proposed hierarchical design attempts to balance these constraints through explicit layering and policy-mediated module activation.

\subsection{The Compute Allocation Problem}
One manifestation of this orchestration challenge is inefficient compute allocation during typical classroom activity. To illustrate the practical inefficiency of continuous orchestration, consider a standard 60-minute lecture divided into distinct pedagogical phases: an initial 10 minutes for attendance taking, 30 minutes of passive video presentation where cognitive load is low, a 15-minute high-engagement Q\&A session, and a 5-minute dismissal period.

A naive edge deployment might execute face detection, pose estimation, and ASR continuously at 30 frames per second for the full hour, consuming:
\begin{equation}
C_{naive} = 60 \times 60 \times 30 = 108,000 \text{ inference cycles}
\end{equation}

However, heavy compute is actually only operationally justified during the attendance phase (10 minutes) and the active Q\&A session (15 minutes). The justified cycle count is significantly lower:
\begin{equation}
C_{justified} = (10 + 15) \times 60 \times 30 = 45,000 \text{ inference cycles}
\end{equation}

In this scenario, the naive system expends roughly 63,000 cycles performing scanning that is not operationally justified. The proposed framework dynamically suppresses these unnecessary cycles, maintaining functional coverage only when dictated by a defined operational policy.

% ==========================================
% IV. HIERARCHICAL CONTROL PLANE
% ==========================================
\section{Hierarchical Control Plane Abstraction}

To address these orchestration constraints, we assume a layered execution environment that supervises module activation. The logical control abstraction is formalized as a supervisory automaton governing module activation. These logical divisions operate within the broader runtime architecture, maintaining strict logical separation from the underlying data plane.

\subsection{Supervisory Automaton Formalization}
Formally, let $M$ represent the set of available perception modules (e.g., vision, audio). Let $H: M \rightarrow \{\text{healthy, degraded, failed}\}$ describe the current health state of each module. Let $P(t)$ be the active policy state at time $t$, and let $B_{remaining}$ represent the remaining computational budget for the day. 

We define a governance activation function that outputs the active module set $A(t) \subseteq M$:
\begin{equation}
A(t) = f(P(t), H(M), B_{remaining})
\end{equation}

This establishes a formal state machine in which module activation is resolved deterministically based on the current policy phase, the hardware's health, and operational limits \cite{b26}. To prevent race-induced nondeterminism during asynchronous health updates, the function $f$ is deterministic and side-effect free with respect to the perception modules, executed within a single-threaded governance loop.

% --- LOGICAL ABSTRACTION ---
The Logical Control Abstraction separates responsibilities vertically. Raw perception data is restricted entirely to the lowest logical boundary, ensuring that Governance only processes aggregated statistics.

\subsection{Typed Context Vectors as Coordination Boundaries}
Maintaining strict separation between architectural layers requires more than an interface; it requires a \textbf{coordination-boundary mechanism}. Communication across layers is restricted to typed and bounded context vectors:
\begin{equation}
\vec{C}_{Perc \to Reas} = \{(event\_type, zone, timestamp)\}
\end{equation}
By receiving only abstracted event tuples via $\vec{C}_{Perc \to Reas}$, the Reasoning and Governance layers operate without direct exposure to raw sensory data. Typed vectors constrain semantic propagation so that upper layers receive bounded abstractions instead of high-fidelity signals. Orchestration isolation structurally depends on this restricted cross-layer visibility.

\subsection{Layer Isolation Factor (LIF)}
To evaluate the success of the orchestration topology, we introduce the Layer Isolation Factor (LIF). Measured per fault injection lifecycle, LIF captures containment topology rather than overall uptime probability; it identifies whether an isolated crash propagates into a cascading failure:
\begin{equation}
LIF = \frac{\text{Failures Contained in Origin Layer}}{\text{Total Module Failures}} \times 100\%
\end{equation}
In our evaluations, LIF averaged 95\%, demonstrating strong boundary confinement, though exact containment ratios naturally depend on the specific fault frequency of the underlying modules \cite{b18}.

% ==========================================
% V. COMPUTE JUSTIFICATION MODEL
% ==========================================
\section{Compute Justification Model}

Continuous activation of all perception modules seldom reflects the operational needs of instructional environments. The Compute Justification Model dictates that compute allocation is governed by policy context, not merely energy optimization. The Governance layer gates module execution based on predefined heuristic schedules corresponding to lecture phases, ensuring that inference suppression is driven by contextual operational relevance.

\subsection{Scheduling Formalism and IRG}
We formalize Inference Rate Governance (IRG) as an orchestration-aware compute restraint mechanism rather than generic power-saving logic. IRG constrains unnecessary sensing activation, and this scheduling suppression directly reduces orchestration pressure. Let $C_{sched}(t)$ denote the scheduled inference cycles at time $t$ for a continuous, full-session baseline. Let $J(t) \in \{0,1\}$ denote the binary policy justification signal, where $1$ indicates a phase requiring active sensing (e.g., a Q\&A session) and $0$ indicates a rest phase. The executed inference cycles $C_{exec}(t)$ are defined as:
\begin{equation}
C_{exec}(t) = C_{sched}(t) \cdot J(t)
\end{equation}

Based on this abstraction, the Inference Suppression Ratio (ISR) quantifies the algorithmic compute savings:
\begin{equation}
ISR = 1 - \frac{\sum_t C_{exec}(t)}{\sum_t C_{sched}(t)}
\end{equation}
ISR reflects the proportion of scheduled compute that is intentionally suppressed under policy control. While higher ISR values indicate reduced resource usage, their interpretation depends on alignment with institutional policy rather than raw suppression magnitude.

\subsection{Ethical Compute Utilization (ECU)}
While ISR measures suppression efficiency, Ethical Compute Utilization (ECU) evaluates the percentage of inference cycles executed with a valid policy alignment against the total actual executed cycles:
\begin{equation}
ECU = \frac{\text{Inference Cycles with Valid } J(t)}{\text{Total Executed Cycles}} \times 100\%
\end{equation}
Justification triggers include formal schedule phase transitions or basic heuristic prompts. The operational target for the system is an ECU $> 90\%$.

\subsection{Context-Aware Duty Cycle (CADC)}
The operational footprint of each individual module is captured by the Context-Aware Duty Cycle (CADC), defined as the ratio of a module's active time to the total lecture duration:
\begin{equation}
CADC = \frac{\text{Module Active Time}}{\text{Total Lecture Duration}} \times 100\%
\end{equation}
Under this model, computationally heavy models are restricted to minimal CADC profiles, while lightweight models (such as pose detection) can afford to maintain high CADC values.

\section{Failure Containment Design}

\subsection{Failure Mode Analysis}
Because edge runtimes inevitably experience localized component faults, asynchronous health-report lag, and scheduling jitter, the orchestration layer must provide explicit containment mechanisms. Table I formalizes the failure scenarios and our containment strategies, drawing on dependable computing taxonomies \cite{b18} and common microservice degradation patterns \cite{b24}. Graceful degradation is an orchestration objective, not merely a side effect of modularity. The system prioritizes operational continuity over sensing completeness; fallback sensing preserves partial functionality when primary modules crash.

\textbf{Failure Scenario} & \textbf{Naive Impact} & \textbf{Our Mitigation} \\

Failure isolation is achieved through runtime separation combined with serialized context exchange. Under evaluated scenarios, a crash within the Perception layer typically results in localized termination. The Reasoning and Governance layers, running in separate contexts, continue execution and initiate fallback procedures via the health interface.

\subsection{Abstract State Transitions for Graceful Degradation}
The Governance layer relies on deterministic abstract state transitions to track system health. Transitions between the states—NORMAL, DEGRADED, and SAFE—are executed as logical operations based on available health signals.

The abstract logical system gracefully degrades from NORMAL (all modules) $\to$ DEGRADED (pose-only) $\to$ SAFE (occupancy sensors) based on abstract module health. We do not define the execution semantics or physical state machine implementations here, only the control decisions. The Governance scheduler assumes health signals are natively available from the underlying runtime execution layers.

% ==========================================
% VII. POLICY-AWARE SCHEDULER
% ==========================================
\section{Policy-Aware Scheduler}

\subsection{Operational Budgets}
To prevent excessive resource drain, the Governance layer tracks daily compute and activation budgets for each module:
\begin{equation}
B_{module}(day) \leq B_{max} = 100 \text{ activations/day}
\end{equation}
When the daily operational budget is exhausted, the system automatically falls back to lower-tier operational modes to conserve energy and compute resources.

\subsection{Session Boundary Enforcement}
At the conclusion of a lecture, the Governance layer explicitly triggers teardown procedures to cleanly terminate the active perception processes and reset the logical context state for the next session. This rigid boundary enforcement ensures that no state machine artifacts bleed across distinct pedagogical events.

% ==========================================
% VIII. VALIDATION ABSTRACTION
% ==========================================
\section{Validation via Fault Injection}

While detailed systemic validation belongs to the evaluation layer of this series \cite{b28}, the proposed control-plane behavior was evaluated under fault injection to verify logical isolation. This confirmed that abstract state transitions occur deterministically even when simulated lower-level perception modules timeout or report memory pressure. We explicitly defer claims of system-level chaos survivability, recovery convergence times, or runtime latency guarantees to the validation architecture, focusing here solely on the fact that the control decisions align with the defined policy.

\subsection{Inference Suppression Statistics}
During a simulated 60-minute lecture, the Compute Justification Model achieved a significant reduction in active cycles. The system recorded a 72\% ISR for the heavy vision modules, confirming that resource-intensive capture primarily occurs during justified instructional phases. Similarly, the ASR module reached an 85\% suppression rate, while the lightweight pose estimator remained largely active with only a 12\% ISR.

\subsection{Limitations}
The orchestration framework exposes several operational limitations:
\begin{itemize}
    \item \textbf{Heuristic-Policy Dependence:} The model relies on defined heuristic schedules; spontaneous classroom interaction shifts or organic deviation may result in unintended sensing suppression.
    \item \textbf{Calibration Sensitivity:} Tuning the Inference Suppression Ratio (ISR) to balance operational savings with interactive responsiveness requires site-specific empirical calibration.
    \item \textbf{Scheduling Rigidity:} Rigid enforcement of lecture session boundaries struggles with overlapping room utilization or ad-hoc interactions.
    \item \textbf{Asynchronous Race-Condition Risk:} The abstract state transitions are evaluated via fault injection rather than formal methods; unexpected race conditions may exist within asynchronous health monitoring loops under high edge-runtime contention.
    \item \textbf{Workload Unpredictability:} Heavy vision modules exhibit variable execution times depending on frame complexity, introducing scheduling jitter that synchronous timeout boundaries may misinterpret as module failure.
\end{itemize}

% ==========================================
% XI. DISCUSSION
% ==========================================
\section{Discussion}

Embedding policy constraints directly within the orchestration layer alters how edge systems allocate computational resources. Instead of continuously capturing and processing all available signals in a brute-force manner, the framework selectively enables modules in accordance with predefined institutional boundaries \cite{b4}.

However, deployment calibration remains a practical engineering challenge. Setting the activation thresholds for diverse classroom layouts requires iterative engineering during initial setup. Refining the heuristic triggers is essential to avoid the false suppression of valid engagement signals while still achieving meaningful compute savings. 

Future extensions of this work may incorporate predictive IRG scaling, leveraging machine learning to preemptively anticipate lecture phases and scale module readiness before explicit triggers occur. Additionally, expanding the control plane to handle multi-classroom orchestration across a federated cluster of edge nodes represents a logical next step.

% ==========================================
% XII. CONCLUSION
% ==========================================
\section{Conclusion}

This study investigated whether heterogeneous AI modules operating at the edge can be coordinated through a layered control-plane abstraction that preserves policy-aware activation, fault containment, and deterministic degradation. By separating Perception, Reasoning, and Governance responsibilities and restricting cross-layer communication to typed context vectors, the architecture isolates orchestration faults and prevents localized module crashes from causing cascading pipeline failure.

The Compute Justification Model explicitly aligns module activation with predefined operational phases, confirming that hierarchical orchestration enables deterministic coordination under shared operational constraints. Fault injection within the evaluated orchestration environment confirmed that the control plane reduces unnecessary activation and gracefully degrades functionality when primary perception pipelines fail.

The proposed metrics---ISR, ECU, CADC, and LIF---provide a quantitative framework for analyzing activation governance. Within the ScholarMaster architecture, this framework operates exclusively as the runtime-governance orchestration subsystem---managing deterministic module coordination and activation transitions without evaluating survivability envelopes (Paper 10), proposing new federated models (Paper 13), or defining irreversible privacy architectures (Paper 17).
