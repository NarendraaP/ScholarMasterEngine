% ABSTRACT
% ==========================================
\begin{abstract}
Institutional attendance verification presents a practical deployment challenge: large student populations must be processed quickly while minimizing operational overhead and impersonation risk. Although facial recognition is frequently proposed as an automated solution, many existing implementations rely on cloud services or report only embedding-level accuracy without examining retrieval behavior under real-time open-set conditions.

This work examines whether biometric identification can operate entirely on edge hardware at institutional scale—up to 100,000 identities—while still meeting strict real-time constraints. The proposed retrieval-focused pipeline segment utilizes Hierarchical Navigable Small World (HNSW) indexing and introduces a Local Density Consistency Criterion (LDCC) to improve robustness when unknown identities are present, assuming deep embeddings are provided externally.

Experiments conducted on an edge hardware platform reveal empirically logarithmic retrieval scaling. Even with a 100K identity registry, mean retrieval latency remains below one millisecond. Under controlled open-set testing with 20\% unknown probes, the pipeline maintains a 99.8\% unknown rejection rate while sustaining throughput above 30 frames per second in a single-stream configuration. By isolating this retrieval step, local execution avoids transmission during retrieval, supporting efficient identity resolution without cloud dependency.
\end{abstract}

% I. INTRODUCTION
% ==========================================
\section{Introduction}

Real-time identity verification within large academic institutions introduces a practical systems constraint: attendance must be validated quickly while avoiding operational disruption inside classrooms. Traditional roll-call procedures scale poorly as enrollment increases and remain vulnerable to impersonation. Automated biometric verification therefore represents a natural technological alternative, provided that the system can operate within strict latency limits.

However, digitizing attendance verification introduces several engineering challenges. Network connectivity within campus environments can be inconsistent, particularly during peak usage hours. Systems that depend on external cloud APIs are therefore exposed to unpredictable latency and bandwidth limitations. A viable institutional solution must instead operate autonomously at the edge, processing video streams locally without requiring synchronous remote services \cite{b1}.

Within an edge-based deployment pipeline, the primary bottleneck shifts from neural inference to identity retrieval. While compact neural networks (e.g., MobileNets \cite{b4}) can efficiently produce embeddings, locating the correct identity within a large gallery often becomes the dominant computational cost. While linear search across stored embeddings works for small cohorts (e.g., fewer than 50 identities), performance degrades rapidly as the gallery grows. At six-figure registry sizes, brute-force vector comparison can become the dominant latency component, regardless of how efficient the neural inference stage may be \cite{b2}.

\subsection{Retrieval Latency Budget}
Real-time streaming places strict bounds on the allowable processing time for each frame. To sustain real-time video at 30 FPS, total processing time per frame must remain within approximately 33 milliseconds:
\begin{equation}
T_{total} = T_{detect} + T_{align} + T_{embed} + T_{retrieve}
\end{equation}
Empirical profiling on edge hardware indicates that detection and alignment consume approximately 4 ms, while embedding extraction requires 28 ms. This leaves only a narrow margin for retrieval. In practice, once embedding time approaches 28 ms, even an additional 5 ms retrieval delay can destabilize the video stream. The requirement for sub-millisecond retrieval arises primarily from operational constraints rather than theoretical optimization.

The present analysis focuses specifically on the retrieval stage under strict latency constraints. We demonstrate that graph-based indexing via HNSW achieves a mean retrieval latency of 0.419 ms at 100K scale. Open-set stress testing confirms stable streaming performance in a single-face gate deployment scenario.

\textbf{Ethics Statement:} This research utilized public datasets (LFW) and synthetic vectors. No personally identifiable information (PII) from real students was used for model training or benchmarking. All experiments align with institutional data privacy policies.

\subsection{Relation to the Ecosystem and Scope Limitation}
Within the broader ScholarMaster edge analytics ecosystem, this study focuses specifically on the execution and retrieval layer responsible for identity retrieval under strict latency constraints. To adhere to academic integrity and avoid scope overlap with companion studies, we explicitly focus on \textbf{algorithmic scalability} (HNSW vs. Linear) and \textbf{retrieval accuracy} under streaming constraints. This module focuses exclusively on identity retrieval and does not own the vision detection models or deep learning architectures. While local processing provides inherent data-transmission boundaries, the formal cryptographic protocols and volatile-memory privacy architectures required for GDPR-aligned deployment are outside the scope of this specific algorithmic evaluation. 

\subsection{Reproducibility}
To facilitate peer validation, the core indexing logic and evaluation scripts are available as an open-source artifact \cite{scholarmaster_repo}. Note that the repository contains code only; no PII or biological data is hosted.

% II. RETRIEVAL BOTTLENECK AT INSTITUTIONAL SCALE

\section{Retrieval Bottleneck at Institutional Scale}

Biometric retrieval behavior changes substantially once identity registries reach institutional scale. This work focuses on institutional-scale deployments involving approximately $10^4$--$10^5$ identities, which differ fundamentally from web-scale systems designed for billions of vectors. At the campus level, early automation initiatives often relied on RFID or NFC-based attendance systems. Although these solutions improved speed compared to manual roll calls, they introduced a proxy vulnerability: possession of a card does not confirm the identity of its holder \cite{b1}. Min-Allah et al. \cite{b8} noted that biometric verification is an effective countermeasure to attendance fraud. However, contact-based systems such as fingerprint scanners raise hygiene concerns in high-traffic environments.

Cloud-based APIs provide recognition capabilities but are poorly suited for continuous real-time video streams. Transmitting high-resolution frames across campus networks introduces unavoidable latency. Reported round-trip delays can range from several hundred milliseconds to multiple seconds per face, particularly during peak usage \cite{b9}. For live ingress monitoring, such delays are unacceptable. Zhou et al. \cite{b2} advocated for processing data closer to the source to reduce this bandwidth load. 

Most academic research in face recognition emphasizes embedding discrimination performance, reporting high benchmark accuracy on datasets such as LFW or MegaFace. However, retrieval cost is often omitted from evaluation. When the gallery size grows beyond 10,000 identities, exhaustive cosine comparison quickly becomes the dominant computational burden.

For a gallery of 100,000 identities with 512-dimensional embeddings, brute-force cosine similarity involves approximately 51.2 million multiply-add operations per query. In our single-threaded CPU implementation, this results in an average retrieval time of 55 ms—far exceeding the available latency budget for real-time streaming. At this scale, retrieval complexity becomes a principal deployment constraint.

Table \ref{tab:sota_constraints} summarizes representative algorithms under institutional-scale constraints. While state-of-the-art embedding models achieve high accuracy on relatively small galleries, they do not report performance under large-scale open-set conditions. In contrast, the proposed pipeline maintains both discrimination performance and real-time throughput at 100K scale.

% III. EMBEDDING GEOMETRY ASSUMPTIONS
% ==========================================
\section{Embedding Geometry Assumptions}

We assume that the deep feature embeddings provided to the retrieval layer utilize margin-induced compactness (such as ArcFace). Conventional Softmax-based training is primarily optimized for closed-set classification. While effective for label separation, it does not explicitly enforce compact intra-class clustering in embedding space. As a consequence, feature overlap between identities can increase false acceptance rates when operating under open-set conditions \cite{b11}.

By utilizing embeddings trained with an additive angular margin penalty in hyperspherical space \cite{b5}, the retrieval layer benefits from tightly clustered intra-class samples and wide inter-class separation. The margin-induced compactness is particularly important for distance-based retrieval. Open-set identification depends on reliable similarity thresholding. If embeddings form well-separated, dense clusters, nearest-neighbor search combined with threshold gating becomes more stable and less sensitive to boundary ambiguity.

% ==========================================
% IV. GRAPH-BASED INDEX CONSTRUCTION
% ==========================================
\section{Graph-Based Index Construction}

To address the retrieval bottleneck introduced by large galleries, the proposed retrieval-focused pipeline segment employs Hierarchical Navigable Small World (HNSW) indexing. HNSW constructs a multi-layer proximity graph inspired by principles from small-world network theory. Lower layers contain dense local connections across all vectors, while higher layers include progressively fewer nodes connected through longer-range links. 

Search begins at the top sparse layer and proceeds through a greedy traversal toward closer nodes, descending layer by layer until convergence \cite{b7}. Empirically, search complexity follows a logarithmic trend:
\begin{equation}
T(N) = a \log(N) + b
\end{equation}
This structure allows efficient approximate nearest neighbor retrieval even in high-dimensional embedding spaces. Tree-based methods often degrade substantially in 512-dimensional space due to the curse of dimensionality \cite{b12}. In our experiments, KD-Tree throughput dropped to approximately 7 FPS, confirming its unsuitability for deep embedding retrieval at scale.

Figure \ref{fig:arch} illustrates the execution scope. The retrieval segment assumes that upstream vision layers provide the 512-dimensional deep embedding vectors. These vectors are then queried against the HNSW index. A lightweight temporal verification buffer smooths predictions across consecutive frames to prevent output flicker.

\subsection{Precision Optimization}
To further optimize edge performance, we employ half-precision (FP16) representation:
\begin{equation}
v_{fp16} = \text{cast}_{fp16}(v_{fp32})
\end{equation}
Since embeddings are normalized to unit magnitude, the reduction from 32-bit to 16-bit precision introduces only minor numerical distortion. In our ablation study, the observed accuracy difference was only 0.03\%, while memory throughput effectively doubled. This reduction tends to improve indexing efficiency and retrieval efficiency on unified-memory architectures, aligning with principles established by Gholami et al. \cite{b14}.

% ==========================================
% V. LOCAL DENSITY CONSISTENCY CRITERION
% ==========================================
\section{Local Density Consistency Criterion (LDCC)}

Open-set biometric identification introduces an additional challenge beyond nearest-neighbor retrieval. In high-dimensional embedding spaces, relying solely on nearest-neighbor similarity may be insufficient for reliable identification. A single high cosine similarity score does not necessarily guarantee a correct identity match. In sparse regions of the embedding space, hubness effects may produce misleading neighbors, especially when dealing with large galleries.

To improve robustness, we introduce the Local Density Consistency Criterion (LDCC). Instead of accepting a match purely on similarity, we additionally verify that the candidate identity lies within a locally coherent neighborhood structure. A probe is accepted only if both conditions are satisfied:
\begin{equation}
\cos(q, v_1) > \tau \quad \land \quad \frac{1}{k}\sum_{i=1}^{k} ||v_i - \bar{v}||^2 < \epsilon
\end{equation}
where $v_i$ are the top-$k$ nearest neighbors of probe $q$, $\bar{v}$ is their centroid, $k=5$ in all experiments, $\tau=0.75$, and $\epsilon=0.02$. 

The first condition ensures sufficient angular similarity. The second verifies that the neighborhood forms a compact cluster rather than an isolated point. Together, these gates help reduce false acceptance caused by structural irregularities in the embedding space.

\begin{algorithm}[H]
\caption{High-Throughput Retrieval Logic}
\begin{algorithmic}[1]
\small
\STATE Input: Vector $vector_{norm}$, Index $HNSW$
\STATE Output: Identity $ID$, Confidence
\STATE $(neighbors, sims) \leftarrow HNSW.search(vector_{norm}, k=5)$
\STATE $id \leftarrow neighbors[0]$
\STATE $similarity \leftarrow sims[0]$
\STATE $density \leftarrow Variance(neighbors)$
\IF{$similarity > \tau$ and $density < \epsilon$}
    \RETURN $id, similarity$
\ELSE
    \RETURN Unknown, 0.0
\ENDIF
\end{algorithmic}
\label{fig:algo}
\end{algorithm}

\subsection{Index Maintenance Strategy}
To avoid downtime during enrollment, we implement a buffered update mechanism. New embeddings are temporarily stored in a flat structure. Once the buffer accumulates 50 entries, a background thread merges them into the primary HNSW index. During early testing, merging occasionally introduced brief inference stalls. This was mitigated by assigning the merge process to a lower-priority CPU core. Deletions are handled via a soft-delete bitmask to prevent index reconstruction. This strategy ensures continuous operation during incremental growth.

\section{Experimental Evaluation}

\subsection{Evaluation Setup}
To evaluate deployment feasibility under institutional conditions, the pipeline was tested using controlled latency benchmarks and synthetic large-scale embedding distributions. Experiments were conducted on an edge computing node using PyTorch 2.0 and FAISS 1.7.4. Retrieval operations remained CPU-bound within FAISS to isolate indexing behavior. Latency results reflect the mean of 10,000 independent queries to ensure statistical stability. CPU frequency scaling was disabled to prevent timing fluctuations during sub-millisecond measurement.

Because public datasets containing 100K labeled identities under open-set protocols are limited, synthetic hypersphere-distributed vectors were used to stress-test retrieval scaling. While this provides a clean baseline for indexing evaluation, real-world embeddings exhibit non-uniform clustering. Consequently, synthetic results represent a controlled upper-bound estimate of retrieval efficiency. The purpose here is not to simulate real-world identity distributions, but to isolate retrieval mechanics independent of feature extraction variability.

\subsection{Latency Scaling}
Gallery sizes of $N \in \{100, 1K, 10K, 50K, 100K\}$ were evaluated. Measured latency follows a largely logarithmic trend. Even at 100K identities, average retrieval latency remains 0.419 ms, with p99 latency below 1.1 ms (Table \ref{tab_scalability}). This suggests that HNSW preserves sub-millisecond performance at institutional scale. Unlike brute-force search, retrieval time does not grow linearly with gallery size, making real-time operation feasible within the 33 ms frame budget.

% VII. DEPLOYMENT AND DATA HANDLING

\section{Deployment and Data Handling}
To support high-throughput retrieval without incurring cloud latency, the algorithm utilizes a strictly local processing model. Video frames are loaded into memory, processed, and immediately overwritten. Local execution avoids transmission during retrieval. Embeddings are stored encrypted at rest; privacy architecture is detailed in companion studies \cite{p3}. By enforcing a single-frame execution window, the algorithm is architecturally constrained to momentary retrieval.

% ==========================================
% VIII. DISCUSSION
% ==========================================
\section{Discussion}

From an algorithmic perspective, the results highlight that identity retrieval—not feature extraction—often becomes the dominant constraint in edge-based biometric deployments. Modern embedding models already provide strong discriminative performance. However, without scalable indexing, these embeddings cannot be deployed under strict real-time streaming conditions.

When attention shifts from model accuracy alone toward retrieval complexity, this work demonstrates that sub-millisecond search is achievable on edge hardware. The elimination of cloud dependencies further improves deployment reliability. During peak campus hours, the pipeline operated without external bandwidth requirements, avoiding latency spikes common in cloud-tethered architectures.

Separating embedding geometry from indexing mechanics clarifies an important algorithmic principle: high-quality embeddings are necessary but insufficient. Efficient search structures help complete the pipeline. This framework ensures that identity vectors remain locally contained, satisfying constraints where biometric data is neither transmitted nor aggregated externally during retrieval.

% ==========================================
% IX. CONCLUSION
% ==========================================
\section{Conclusion}
This work examined whether institutional-scale biometric identification can operate entirely on edge hardware when retrieval latency is treated as a primary algorithmic constraint. By integrating margin-based embeddings with HNSW indexing and LDCC gating, the proposed algorithm maintains 99.82\% LFW accuracy while achieving sub-millisecond retrieval at 100K scale. 

Real-time performance above 30 FPS is sustained without reliance on cloud connectivity. The primary contribution lies not in improving embedding discrimination itself but in addressing the retrieval bottleneck that often limits practical deployment. Graph-based indexing therefore enables practical biometric identification at institutional scale while maintaining fully local processing on edge devices.
