% ABSTRACT
% ==========================================
\begin{abstract}
The evaluation of edge AI systems under adversarial conditions requires a rigorous formalization of their defensive boundaries. While prior work established the architectural doctrine of irreversibility and its runtime enforcement mechanisms, the exact security boundaries, formal adversary definitions, and assumed trust models require explicit mathematical formulation. This paper formally defines the Threat Model, Information Flow boundaries, and Trusted Computing Base (TCB) for architecturally irreversible edge AI systems. We establish a tiered adversary classification algebra ($A_0$ to $A_5$) mapping observer capabilities to memory, network, and kernel domains. We formalize the system using a Non-Interference information flow model and express system state transitions using Metric Temporal Logic (MTL), demonstrating that high-sensitivity raw biometric data cannot propagate to persistent sinks under the defined assumptions. Furthermore, we explicitly demarcate the system's operational scope, validating defense against institutional root adversaries ($A_3$) while analyzing the collapse of invariants under kernel-level ($A_4$) and physical hardware compromises ($A_5$). By delineating the minimal TCB, we quantify the residual attack surface, including information-theoretic bounds on Model Inversion attacks. Finally, we formulate and justify four bounded security theorems: Pixel-Space Non-Reconstructability, Bounded Exposure Window ($\Delta \le 33$ms), Governance Non-Bypass, and Fail-Closed State Reachability, conditionally grounded on empirical runtime validation and mechanized TLA+ model checking. This work provides the formal security calculus necessary to evaluate privacy-by-architecture systems under rigorous adversarial scrutiny.
\end{abstract}

Adversary Capability Algebra, Trusted Computing Base Minimization, Information-Flow Non-Interference, Temporal-Logic Verification, Bounded Security Assumptions, TLA+ State Constraints.

\section{Introduction}

\subsection{Threat-Model Ambiguity in Privacy-Preserving AI}
Many privacy-preserving AI systems claim robust protection without formally defining the scope of the adversary. Literature frequently blurs the distinction between user-space application compromise and institutional root compromise, often omitting explicit Trusted Computing Base (TCB) assumptions. Security claims are mathematically meaningless without bounded adversary assumptions. Empirical runtime behavior alone cannot establish formal privacy guarantees; architectural privacy requires explicit trust formalization. Without defined information-flow constraints, edge-AI systems cannot rigorously differentiate between benign operational exposure and catastrophic privacy leakage.

\subsection{The Security Framing Gap}
To mitigate systemic privacy risks, defensive frameworks based on \textit{Architectural Irreversibility} \cite{b1} have been proposed and validated through runtime enforcement \cite{b30_cps}. However, architectural intent is insufficient without a mathematically defined boundary of trust \cite{b1}. If an architecture claims to destroy raw biometric data within $33$ms, does that property hold against an institutional root administrator or a compromised OS kernel?

The dominant thesis of this paper is that \textbf{bounded privacy guarantees require explicit adversary and TCB formalization}. This paper bridges the security framing gap by providing the formal threat model, information-flow constraints, and trust assumptions under which irreversible edge analytics are valid. Within the ScholarMaster architecture, this subsystem defines adversary boundaries, TCB assumptions, information-flow constraints, and temporal security invariants only. It does not implement runtime crash handlers (Paper 18), define federated optimization (Paper 14), synthesize deployment architecture (Paper 20), derive spatiotemporal trajectory logic (Paper 21), or construct sociological trust models (Paper 16).

\subsection{Scope and Formal Dependency Hierarchy}
This paper does not introduce new architectural layers or spatiotemporal theorems. Instead, it constructs a progressive formal dependency chain:
\begin{itemize}
    \item \textbf{Adversary Algebra:} Defines capability bounds.
    \item \textbf{TCB Formalization:} Defines the trusted substrate.
    \item \textbf{Noninterference:} Defines information isolation.
    \item \textbf{MTL Constraints:} Defines temporal enforcement.
    \item \textbf{TLA+ Verification:} Defines bounded consistency checking.
    \item \textbf{Security Theorems:} Derives bounded privacy guarantees.
\end{itemize}

By defining these bounds, we align the evaluation of the system with established principles of formal secure systems design and model checking \cite{b10}.

% II. FORMAL ADVERSARY MODEL
% ==========================================
\section{Formal Adversary Classification Model}
To analyze system resilience, we must first formalize the capabilities of the attacker. We adapt standard threat modeling \cite{b2} and extend it for cyber-physical edge nodes. This formal classification extends the architectural threat overview presented in prior reference architecture work \cite{b6} by introducing mathematical capability tuples, explicit bounding assumptions, and TCB-grounded proof conditions.



Let an Adversary $A$ be defined by a tuple of capabilities:
\begin{equation}
A = \langle \mathcal{O}, \mathcal{M}, \mathcal{E} \rangle
\end{equation}
where:
\begin{itemize}
    \item $\mathcal{O}$ is the set of observable states (network packets, memory regions, file systems).
    \item $\mathcal{M}$ is the set of modifiable states (packet injection, memory writing, file alteration).
    \item $\mathcal{E}$ is the execution privilege level (Ring 3 user-space, Ring 0 kernel, Ring -1 hypervisor/physical).
\end{itemize}

We formalize a tiered hierarchy of adversaries to precisely bound the limits of the architectural claims.

\subsection{Formal Threat Model Assumptions}
To eliminate theoretical gaps and construct rigorous proofs, we establish explicit boundary conditions for the operational environment. The formal security guarantees in this paper are strictly predicated on the following axioms:

\begin{assumption}[$A_{HW}$: Hardware Isolation]
Edge node hardware correctly enforces Input-Output Memory Management Unit (IOMMU) domains and memory isolation, preventing unauthorized PCIe/Thunderbolt Direct Memory Access (DMA) attacks from bypassing virtual memory boundaries.
\end{assumption}

\begin{assumption}[$A_{PHYS}$: Physical Security]
No adversary possesses the physical capability or operational window necessary to perform DRAM decapping, hardware bus probing, or cold-boot extraction.
\end{assumption}

\begin{assumption}[$A_{SPEC}$: Microarchitectural Security]
Speculative execution leakage (e.g., Spectre-class vulnerabilities) is effectively mitigated at the OS kernel level via software speculation barriers and SMT isolation.
\end{assumption}

These assumptions do not weaken the proofs; rather, they mathematically bound the adversary model, explicitly shifting physical and microarchitectural extraction outside the formal scope to preserve the structural integrity of the software-architectural proofs.

\subsection{$A_0$: Passive Observer}
\begin{itemize}
    \item $\mathcal{O}_{A0} = \{ \text{Ciphertext Network Traffic}, \text{Physical LEDs} \}$
    \item $\mathcal{M}_{A0} = \emptyset$
    \item $\mathcal{E}_{A0} = \text{None}$
    \item \textit{Profile:} A student or external actor observing the physical device or sniffing WiFi packets. Defeated by standard mTLS and chassis enclosures.
\end{itemize}

\subsection{$A_1$: User-Space Local Adversary}
\begin{itemize}
    \item $\mathcal{O}_{A1} = \{ \text{User-owned processes}, \text{World-readable files}, \text{Top/PS output} \}$
    \item $\mathcal{M}_{A1} = \{ \text{User-owned process termination}, \text{Local socket binding} \}$
    \item $\mathcal{E}_{A1} = \text{Ring 3 (UID} \neq 0\text{)}$
    \item \textit{Profile:} An attacker who obtains SSH access via a compromised student/faculty non-root credential. Blocked by OS-level virtual memory isolation.
\end{itemize}

\subsection{$A_2$: Remote Network Adversary}
\begin{itemize}
    \item $\mathcal{O}_{A2} = \{ \text{Network metadata}, \text{Ciphertext} \}$
    \item $\mathcal{M}_{A2} = \{ \text{Packet Drop}, \text{Packet Delay}, \text{Packet Replay} \}$
    \item $\mathcal{E}_{A2} = \text{None}$
    \item \textit{Profile:} A network administrator or ISP executing man-in-the-middle (MITM) or denial-of-service (DoS) attacks. Defeated by authenticated payloads and fail-closed network timeout logic.
\end{itemize}

\subsection{$A_3$: Institutional Administrator (Root)}
\begin{itemize}
    \item $\mathcal{O}_{A3} = \{ \text{Entire Filesystem}, \text{Active RAM via \texttt{/dev/mem}} \}$
    \item $\mathcal{M}_{A3} = \{ \text{Service Restart}, \text{File Deletion}, \text{Process Debugging (\texttt{ptrace})} \}$
    \item $\mathcal{E}_{A3} = \text{Ring 3 (UID = 0)}$
    \item \textit{Profile:} The primary threat actor modeled in privacy-by-architecture. A malicious or compromised IT administrator attempting retrospective mass surveillance. 
    \item \textit{Critical Assumption:} $A_3$ explicitly assumes Secure Boot with kernel module signing enforced and an immutable root filesystem. Violation of these assumptions (e.g., loading unsigned kernel modules or using \texttt{LD\_PRELOAD} to hook allocators globally) bypasses the TCB and escalates the adversary to $A_4$.
\end{itemize}

\subsection{$A_4$: Kernel-Level Adversary (Out of Scope)}
\begin{itemize}
    \item $\mathcal{O}_{A4} = \text{Universal System State}$
    \item $\mathcal{M}_{A4} = \{ \text{Arbitrary Read/Write}, \text{Page Table Manipulation}, \text{Scheduler Hijacking} \}$
    \item $\mathcal{E}_{A4} = \text{Ring 0}$
    \item \textit{Profile:} An attacker exploiting a zero-day in the Linux kernel or escalating privileges past a weakened $A_3$ state. \textbf{Explicitly out of scope.} The architectural claims depend wholly on the kernel's ability to enforce isolation.
\end{itemize}

\subsection{$A_5$: Physical / Hardware Adversary (Out of Scope)}
\begin{itemize}
    \item $\mathcal{O}_{A5} = \{ \text{DRAM Remanence}, \text{EM Emanations}, \text{Bus Probing} \}$
    \item $\mathcal{M}_{A5} = \{ \text{Cold Boot Extraction}, \text{Voltage Glitching}, \text{JTAG Injection} \}$
    \item $\mathcal{E}_{A5} = \text{Physical / Hardware Level}$
    \item \textit{Profile:} State-actor or physical thief extracting RAM modules. \textbf{Explicitly out of scope} (Bounded by assumption $A_{PHYS}$) for software-enforced architectures lacking Transparent Memory Encryption (TME) \cite{b4}.
\end{itemize}

% III. INFORMATION FLOW & NON-INTERFERENCE
% ==========================================
\section{Information Flow and Non-Interference Model}
To formally verify the architectural claims against attackers $A_0 \dots A_3$, we define the system using a Trace-Based Information Flow / Non-Interference model, built upon the foundations laid by Denning \cite{b12} and formalized by Goguen and Meseguer \cite{b8}.

\subsection{Security Domains and State Indistinguishability}
Following the lattice model of information flow \cite{b12}, we define two strict security domains:
\begin{itemize}
    \item $\mathcal{D}_{High}$: Volatile memory containing high-sensitivity raw biometric data (RGB frames, audio waveforms).
    \item $\mathcal{D}_{Low}$: Persistent storage and network egress containing anonymized metadata and encrypted logic logs.
\end{itemize}

Let $S$ be the set of all possible system states. We define an observation function $obs_{L}(s)$ which yields the state of $\mathcal{D}_{Low}$ in system state $s$. Two states $s_1$ and $s_2$ are indistinguishable to an $A_3$ adversary inspecting persistent storage if $obs_{L}(s_1) = obs_{L}(s_2)$, denoted as $s_1 \sim_L s_2$ \cite{b11}.

\subsection{Formal Threat Model Equation}
The core architectural claim is a strict one-way information flow prohibiting historical raw data extraction. We formalize this using a system tuple $\mathcal{S}$.

Let $\mathcal{S} = \langle TCB, \mathcal{U}, A_i \rangle$ represent the runtime system, where $TCB$ is the trusted computing base and $\mathcal{U}$ represents untrusted architectural components (e.g., neural network weights, UI). Let $X_{t < t_{now} - \Delta}$ represent raw biometric data existing prior to the configured TTL threshold $\Delta$. 

The system's fundamental security claim holds if and only if:
\begin{equation}
\forall A_i \in \{A_0, A_1, A_2, A_3\} : compromise(A_i) \land intact(TCB) \implies \neg extract(X_{t < t_{now} - \Delta})
\end{equation}

This equation mathematically asserts that as long as the adversary's capability is bounded by $A_3$ and the TCB remains unviolated (no kernel compromise), retrospective extraction of raw data is strictly impossible.

\subsection{Information Funneling and Dimensionality Reduction}
The only permissible flow from $\mathcal{D}_{High} \to \mathcal{D}_{Low}$ is through the transformation function $F_{irreversible}$:
\begin{equation}
F_{irreversible}: \mathbb{R}^{H \times W \times 3} \to \mathbb{R}^{d_{meta}}
\end{equation}
Where $H \times W \times 3$ represents the continuous high-fidelity pixel space, and $d_{meta}$ represents the discrete low-dimensional semantic space (e.g., boolean engagement flags or zone coordinates). The mathematical non-reconstructability of this transformation---including the degree-of-freedom collapse, non-injectivity, and conditional entropy analysis---has been established in prior foundational work \cite{b8, b11}. For the purposes of this security analysis, we note that $F_{irreversible}$ is a many-to-one surjective mapping with immense entropy loss, and the flow preserves Non-Interference with respect to precise identity reconstruction \cite{b23}.

\section{State Transitions}
To rigorously map runtime enforcement mechanisms into mathematical proofs, we define the formal state space. The specific Temporal Logic formalizations (MTL) restricting these transitions are detailed in Appendix A.

\subsection{Formal State Space Definition}
Let the system state space $\mathcal{S}$ be defined by the tuple:
\begin{equation}
s = \langle M_{high}, M_{low}, \mathcal{P}, Net, Mode \rangle
\end{equation}
where $M_{high}$ is the state of volatile raw memory, $M_{low}$ is persistent storage, $\mathcal{P}$ represents active processes, $Net$ is the egress queue, and $Mode \in \{NORMAL, DEGRADED, HALT\}$. 
We define the state transition function $\delta : \mathcal{S} \times E \to \mathcal{S}'$, where $E$ is an internal or external event (e.g., timer tick, hardware fault). 

We define the following predicates over a data buffer $b \in M_{high}$:
\begin{itemize}
    \item $Alloc(b)$: Buffer $b$ is allocated in volatile memory.
    \item $Raw(b)$: Buffer $b$ contains high-fidelity raw biometric data.
    \item $Zeroed(b)$: Buffer $b$ has been securely overwritten with zeros.
    \item $Emit(b)$: The contents of buffer $b$ are pushed to $Net$.
    \item $Gov(b)$: The contents of buffer $b$ have passed Governance checks.
\end{itemize}

\section{Trusted Computing Base (TCB)}
The Trusted Computing Base (TCB) comprises the totality of hardware, firmware, and software components that are critical to system security. Minimizing the TCB is a fundamental goal of secure system design \cite{b3}. 



\subsection{Explicit TCB Formalization}
Let the total system environment consist of the union of the Trusted Computing Base ($TCB$) and untrusted components ($\mathcal{U}$). We formally define the TCB as the set:
\begin{equation}
TCB = \{ C_{boot}, C_{kernel}, C_{alloc}, C_{sched}, C_{gov} \}
\end{equation}
We assert the fundamental trust axiom necessary for system integrity:
\begin{equation}
\forall c \in TCB : Trusted(c) \quad \land \quad \exists u \in \mathcal{U} : \neg Trusted(u)
\end{equation}

\subsection{Kernel Dependency Assumptions}
The architectural guarantees are conditionally dependent on the formal correctness of the OS kernel, governed by the bounding axioms $A_{HW}$ and $A_{SPEC}$. We explicitly define these kernel dependencies as:
\begin{assumption}[$K_1$: Memory Isolation] 
The kernel correctly enforces virtual memory boundaries, preventing Ring 3 process A from reading the address space of process B. 
\end{assumption}
\begin{assumption}[$K_2$: mlock Semantics] 
The kernel strictly honors the \texttt{mlock()} system call, mathematically guaranteeing that locked pages are never evicted to persistent swap space. 
\end{assumption}
\begin{assumption}[$K_3$: Scheduler Fairness] 
The OS scheduler strictly honors POSIX \texttt{SCHED\_FIFO} real-time priorities, ensuring the Watchdog process is never starved by user-space compute threads. 
\end{assumption}
\begin{assumption}[$K_4$: IOMMU Isolation]
Derived from $A_{HW}$, the hardware and kernel correctly enforce IOMMU domains with DMA remapping.
\end{assumption}

In addition to the kernel, the TCB inherently includes the \textbf{Compiler Toolchain Trust} (mitigating the classic Thompson "Trusting Trust" attack) and the \textbf{C Standard Library and Dynamic Loader}, which must faithfully execute explicit zeroization requests before returning pages to the OS.

\subsection{Excluded from the TCB: Minimizing Attack Surface}
Minimizing trusted components reduces the unverifiable attack surface. The architecture is mathematically designed to explicitly exclude the following from the TCB:
\begin{itemize}
    \item \textbf{Inference Model Weights:} Neural networks are excluded because mathematical models are inherently susceptible to adversarial perturbation and weight poisoning. By placing models outside the TCB, we assert that maliciously altered weights cannot bypass the architectural destruction of memory buffers. Architectural isolation matters more than model trustworthiness.
    \item \textbf{Application APIs and UIs:} Query interfaces and user-facing dashboards are assumed susceptible to injection attacks, rendering them untrustworthy.
\end{itemize}

% VII. RESIDUAL RISK & INVERSION BOUNDS
% ==========================================
\section{Residual Risk \& Information-Theoretic Bounds}
Security maturity requires acknowledging the limits of any defensive architecture. We must formally analyze Machine Learning inversion attacks using Information Theory.

\subsection{Model Inversion (MI) Bounds}
We analyze Model Inversion attacks \cite{b23} not to claim mathematical impossibility, but to establish underdetermination and entropy collapse. Can an adversary reconstruct a student's exact face from a low-dimensional output embedding $Y \in \mathbb{R}^{512}$?
Let the raw input space be the random variable $X \in \mathbb{R}^{1080 \times 1920 \times 3}$.
The inference model is a deterministic function $f: X \to Y$. 

\textbf{Information-Theoretic Bound:} We analyze this via Shannon Entropy $H$. The conditional entropy $H(X | Y)$ represents the uncertainty remaining about the original image $X$ given the embedding $Y$:
\begin{equation}
H(X | Y) = H(X) - I(X;Y)
\end{equation}
The projection from roughly 6.2 million dimensions down to 512 dimensions is a highly lossy operation. The transformation $f$ is non-injective and information-theoretically many-to-one. Therefore, exact reconstruction of the original preimage $x \in X$ is not uniquely determined by the embedding $Y$.

While generative models (e.g., GANs) can hallucinate a \textit{statistically plausible prior} face that generates embedding $Y$, exact historical reconstruction becomes operationally infeasible under the defined threat model. Because the TCB strictly destroys the raw data, the architectural removal of auxiliary side channels ensures no on-disk hints exist to bridge this entropic gap. 

\subsection{Membership Inference Attacks (MIA)}
If the system participates in Federated Learning to update models, it transmits gradient updates $\nabla \theta$. Membership Inference Attacks \cite{b5} seek to determine if a specific data point $x$ was in the training batch by observing changes in $\theta$. Secret extraction via memorized gradients \cite{b21} is a known risk in high-capacity networks.

We acknowledge MIA as an inherent residual risk in distributed AI. Under $A_0$-$A_3$ adversaries, the exposure is limited to distributional leakage rather than direct data extraction. Formal mitigation relies on implementing Differential Privacy (DP) \cite{b14, b22}, which bounds the adversary's capability by a privacy budget $\epsilon$. The mathematical formalization of the DP mechanism, including sensitivity analysis and noise injection protocols for the federated learning context, is addressed in companion work on intra-campus federated learning \cite{b14, b22}. While DP is an architectural option, its mathematical enforcement is orthogonal to the local runtime irreversibility guaranteed by the TCB.

% VIII. INFORMATION-FLOW NONINTERFERENCE
% ==========================================
\section{Information-Flow Noninterference}

To rigorously prove the separation of biometric data from persistent sinks, we evaluate the architecture using formal Information-Flow Noninterference.

\subsection{Domain Partition}
The system's state space is strictly partitioned into two security domains:
\begin{itemize}
    \item $\mathcal{D}_{High}$: The protected volatile memory space containing raw, high-fidelity biometric data (e.g., RGB pixel arrays, uncompressed audio).
    \item $\mathcal{D}_{Low}$: The observable persistent storage, network egress queues, and semantic metadata logs.
\end{itemize}

\subsection{Two-Trace Equivalence}
The core privacy guarantee is established via two-trace equivalence. Let $tr_1$ and $tr_2$ be two valid execution traces of the system. The system satisfies noninterference if any two traces that have equivalent low-domain inputs ($\sim_L$) produce exactly the same low-domain observations ($obs_L$), regardless of the data in the high domain.
\begin{equation}
\forall tr_1, tr_2 \in Traces : tr_1 \sim_L tr_2 \implies obs_L(tr_1) = obs_L(tr_2)
\end{equation}
This guarantees that an $A_3$ adversary inspecting $\mathcal{D}_{Low}$ cannot deduce any properties of the raw biometric data in $\mathcal{D}_{High}$.

\subsection{Termination-Insensitive Property}
Because the architecture utilizes a fail-closed watchdog that terminates the process (`SIGKILL`) if raw buffers exceed their TTL, an adversary can observe a system halt. Consequently, the architecture satisfies \textit{Termination-Insensitive Noninterference (TINI)}. TINI acknowledges that while the adversary can learn a 1-bit signal (that a termination occurred), the actual payload of $\mathcal{D}_{High}$ remains mathematically unobservable.

\subsection{TLA+ Model Checking and State Bounds}
The noninterference properties and domain partitions were mechanically verified using TLA+ and the TLC model checker. Because concurrent temporal logic models are highly susceptible to state space explosion, the model was computationally bounded. We restricted the verification to a maximum of $N \le 2$ concurrent frame buffers and a discrete temporal step bound of $\Delta t \le 3$. Under these strict computational bounds, the TLC checker exhaustively explored all reachable states and confirmed zero violations of the two-trace equivalence property.

% IX. TIMING CHANNEL MITIGATION
% ==========================================
\section{Timing Channel Mitigation}
To prevent side-channel leakage via execution duration (observable by an $A_0$ adversary), the inference pipeline enforces strict isochronal constraints.

\subsection{Execution Model}
The system utilizes a \textbf{Fixed Computational Graph}. Neural network execution paths are static; there are no data-dependent branching operations that would alter the control flow based on the content of the raw input.

\subsection{Isochronal Constraints}
\begin{itemize}
    \item \textbf{Bounded Jitter:} The inference process runs with real-time scheduling priority, ensuring that preemption is deterministic and jitter is bounded.
    \item \textbf{Constant Upper Bound:} The latency $L(x)$ for processing any input frame $x$ is strictly bounded by $L_{max}$ (e.g., 33ms). If processing completes early, the system waits until $L_{max}$ before emitting the result or accepting the next frame.
\end{itemize}

\subsection{Leakage Claim}
The mutual information between the execution time $T$ and the high-domain input $X$, denoted as $I(T; X)$, is negligible and bounded by the scheduling jitter $\delta_{jitter}$. Consequently, timing leakage is bounded and considered negligible under adversaries $A_0$ through $A_3$.

\section{Formal Security Theorems}

\subsection{Empirical Grounding}
The formal proofs provided below map logical constraints to system states. It is critical to state that all theorems are conditionally bounded by the foundational axioms ($A_{HW}, A_{PHYS}, A_{SPEC}$) and physical/runtime enforcement mechanisms. A theoretical proof of fail-closed semantics is only practically valid because the watchdog timer architecture was empirically shown to execute successfully under adversarial fault injection.

\begin{theorem}[Bounded Pixel-Space Non-Reconstructability]
Under adversary constraints $A_0$ through $A_3$ and foundational assumptions ($A_{HW}, A_{PHYS}, A_{SPEC}$), pixel-space reconstruction from post-boundary representations is architecturally underdetermined and mathematically non-unique.
\end{theorem}
\begin{proof}
Follows directly from the Non-Interference property (Equation 2) under adversary constraints $A_0$ through $A_3$ and intact TCB assumptions. The full Shannon entropy derivation, degree-of-freedom collapse, and formal non-injectivity proof of the transformation function $F_{irreversible}$ are established in prior foundational work \cite{b11}. Under the defined threat model, no residual side-channel copies of the raw matrix $X$ persist in memory to bypass this mathematical bound.
\end{proof}

\begin{theorem}[Probabilistic Noninterference]
If the abstraction function is many-to-one over identity space and no stochastic process is conditioned on raw frame entropy, then the framework satisfies probabilistic noninterference under adversaries $A_0$ through $A_3$.
\end{theorem}
\begin{proof}
Let $X \in \mathcal{D}_{High}$ denote the raw input matrix and $Y \in \mathcal{D}_{Low}$ denote the abstracted semantic output. Probabilistic noninterference requires that the probability distribution of observable low-domain events remains invariant across high-domain inputs that map to the same semantic class. Because $F_{irreversible}$ is a many-to-one projection, multiple distinct biometric preimages $\{x_1, x_2, \dots, x_n\}$ map to the same skeletal representation $y$. Under the TCB assumptions, the execution timing and network emission probabilities are a function of $y$ and the downstream deterministic governance logic, not $x$. Because no stochastic process is seeded by the residual entropy of $X$, the observation distribution $P(obs_L | X = x_i)$ is identical for all $x_i \in f^{-1}(y)$. Therefore, the system preserves trace equivalence in probability.
\end{proof}

\begin{theorem}[Bounded Temporal Exposure]
Raw biometric data exposure to an active $A_3$ (Root) adversary intercepting live memory via OS-level debuggers is strictly bounded by the configured TTL parameter $\Delta$ (e.g., $\Delta \le 33$ms).
\end{theorem}
\begin{proof}
Assume $A_3$ initiates a memory read via \texttt{/dev/mem} at time $T_{attack}$. By the TCB enforcement loop defined in MTL Property 1, any buffer $b$ allocated at $T_{alloc} < T_{attack} - \Delta$ has been subjected to forced zeroization by the real-time priority watchdog. Therefore, the adversary's observational window is mathematically constrained strictly to $T_{attack} - \Delta \le T_{alloc} \le T_{attack}$. Retrospective historical extraction is structurally impossible under a trusted kernel.
\end{proof}

\begin{theorem}[Governance Token Non-Bypass]
Under attacker classes $A_0$ through $A_3$, no post-boundary payload can be emitted to an external sink without the inclusion of a governance approval token evaluated and validated by a TCB-resident module.
\end{theorem}
\begin{proof}
All post-boundary egress relies on authenticated channels managed by the Governance module within the TCB (Section V). Governance approval tokens are evaluated and validated strictly by this TCB-resident module. If an $A_1$ or $A_3$ adversary attempts to emit data via a separate spoofed process, they lack the trusted credentials managed by the TCB to authenticate with the central broker, resulting in the connection being deterministically dropped by the network ingress layer. The specific authentication mechanism (e.g., token signing, mutual TLS) is an implementation detail addressed in companion work on provenance integrity; this theorem establishes only that the governance gate cannot be architecturally bypassed under the defined adversary constraints. This satisfies MTL Property 2 (detailed in Appendix A).
\end{proof}

\begin{theorem}[Fail-Closed State Reachability]
Under non-kernel operational failure conditions (Process Crash, Network Partition, OOM, Power Loss), the system deterministically reaches a secure HALT or DEGRADED state where all privacy invariants are preserved.
\end{theorem}
\begin{proof}
If the main process crashes, OS-level resource reclamation triggers standard cleanup. If the process hangs, the independent Watchdog process (within the TCB) detects the heartbeat timeout and issues a `SIGKILL` (satisfying MTL Property 3). Upon power loss, volatile memory domains ($\mathcal{D}_{High}$) naturally collapse. In all specified conditions, the system transition function $\delta$ moves to a non-operational state without executing a persistent disk write of raw data, thereby preserving Non-Interference.
\end{proof}

\section{Related Work}

The formalization of security boundaries for computing systems has a long tradition. The Trusted Computing Base concept was established by the DoD Orange Book \cite{b3}, and the lattice model of secure information flow by Denning \cite{b12} provides the theoretical foundation for the domain partitioning used here. Goguen and Meseguer's noninterference framework \cite{b8} and its refinement by Sabelfeld and Myers \cite{b11} underpin the two-trace equivalence formulation.

The adversary classification model adapts the Dolev-Yao threat model \cite{b2} to the edge AI context. While Dolev-Yao assumes an omnipotent network adversary, our tiered model explicitly bounds adversary capabilities at each privilege level and identifies the precise boundary ($A_3$/$A_4$) where software-level invariants collapse. This approach aligns with CPS threat modeling methodologies \cite{b30_cps} that distinguish between cyber and physical attack surfaces.

Metric Temporal Logic \cite{b9} and model checking \cite{b10} provide the formal verification tools used to validate security invariants. The TLA+ bounded model checking employed here follows established practice for concurrent system verification, though the application to privacy-by-architecture security properties is novel.

Recent work on Trusted Execution Environments (TEEs) such as Intel SGX \cite{b16} and ARM TrustZone \cite{b17_tz} addresses hardware-level isolation. Our architecture explicitly operates below the TEE assumption boundary, relying instead on software-level TCB minimization for commodity edge hardware.

\subsection{Limitations and Operational Realism}
The formal verification of edge-security architectures contains several structural and methodological boundaries. Operationally, real institutional attack surfaces frequently involve administrator misuse, swap-space persistence, and crash-dump leakage, forcing us to bound our formal claims:
\begin{itemize}
    \item \textbf{Kernel-Compromise Exclusion:} The formal guarantees inherently collapse under a Ring-0 kernel exploit ($A_4$), rendering software-enforced TCB boundaries meaningless against advanced persistent threats.
    \item \textbf{Physical Side-Channel Limits:} The Dolev-Yao-inspired model deliberately excludes physical extraction capabilities ($A_5$), leaving the system unverified against cold-boot attacks or EM emanations without hardware-level TME.
    \item \textbf{State-Space Explosion:} The TLA+ model checking was computationally bounded to $N \le 2$ concurrent frame buffers; verifying the liveness properties against an arbitrary number of asynchronous threads remains computationally intractable.
    \item \textbf{Implementation Divergence:} Machine-checked proofs verify the logical TLA+ state-machine representation, not the underlying C/Python compilation, leaving a residual risk of implementation-versus-model divergence.
    \item \textbf{Microarchitectural Leakage Risk:} The formal information-flow model treats memory isolation as absolute, failing to capture transient execution vulnerabilities (e.g., Spectre) that operate below the architectural abstraction layer.
\end{itemize}

\section{Conclusion}

Security is not an absolute state, but a defined mathematical boundary of assumptions and mitigations. By explicitly defining the attacker capability algebra ($A_0$--$A_5$), establishing bounded physical and hardware axioms, and defining a minimal Trusted Computing Base (TCB), we have isolated the precise conditions under which architectural privacy claims hold. 

We clearly acknowledge that physical DRAM extraction ($A_5$) and kernel compromise ($A_4$) void the software-level invariants. However, under the defined adversary assumptions, we have demonstrated via Information Flow models and Metric Temporal Logic (MTL) that against the most realistic threats to institutional privacy ($A_0$--$A_3$), the system's exposure is bounded. By rigorously defining what the system does \textit{not} do, we provide the necessary logical credibility to evaluate what it \textit{does} achieve. Within the ScholarMaster architecture, this framework operates exclusively as the formal threat-modeling and TCB-analysis subsystem---verifying information-flow boundaries and temporal invariants without modifying crash-enforcement routines, cryptographic audits, or spatial augmented-reality rendering logic. This paper concludes as a bounded formal security analysis, avoiding universal claims of perfect isolation.

\section{Temporal Logic Formalization of Invariants}
The following Metric Temporal Logic (MTL) properties formally restrict the set of valid state transitions $\delta$ described in Section IV. 

\subsection{MTL Property 1: Bounded Temporal Exposure}
The system enforces that any buffer containing raw data must be zeroed within the strict configured temporal window $\Delta_{TTL}$. Using the MTL "eventually within time $c$" operator ($\Diamond_{\le c}$):

\begin{property}[Strict Volatility]
\begin{equation}
\square \left( (Alloc(b) \land Raw(b)) \implies \Diamond_{\le \Delta_{TTL}} Zeroed(b) \right)
\end{equation}
\end{property}
This states that it is \textit{always} ($\square$) true that if a buffer contains raw data, it will \textit{eventually, within $\Delta_{TTL}$ milliseconds}, be explicitly zeroed.

\subsection{MTL Property 2: Governance Non-Bypass}
The system enforces that no data can transition to $Net$ without passing the Governance rules.

\begin{property}[Governance Gate]
\begin{equation}
\square \left( Emit(b) \implies Gov(b) \right)
\end{equation}
\end{property}

\subsection{MTL Property 3: Watchdog Fail-Closed Liveness}
If the main process hangs and fails to zeroize a buffer, the independent watchdog process $W \in \mathcal{P}$ guarantees termination. Let $Timeout(b)$ denote the condition where age of buffer $b$ exceeds $\Delta_{TTL}$.

\begin{property}[Safe Halt]
\begin{equation}
\square \left( Timeout(b) \implies \Diamond_{\le \epsilon} (Mode = HALT) \right)
\end{equation}
\end{property}
Where $\epsilon$ is the scheduling latency of the real-time priority watchdog. This restricts $\delta$ to fail-closed transitions: the system enforces a crash over a privacy violation.

\subsection{TLA+ Model Checking Verification}
To computationally verify the consistency of the state machine defined by these temporal properties, the core memory lifecycle invariants were modeled using TLA+. State-space explosion limits exhaustive verification of arbitrary concurrency. Therefore, the verification was computationally bounded ($N \le 2$ concurrent frame buffers and $\Delta t \le 3$). The model verifies high-level logic abstractions rather than compiled C binaries. Within these bounded assumptions, model checking confirmed the absence of persistence, complementing rather than replacing empirical runtime enforcement.
